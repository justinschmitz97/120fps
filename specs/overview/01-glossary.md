| term | definition |
|---|---|
| PropSchema | One prop's type info: `{ name, kind, values, required, degenerate? }`. Kind is `"boolean"|"string"|"number"|"union"|"array"|"function"|"reactnode"|"object"|"unknown"`. `degenerate` (M60) names why no faithful value could be synthesized (a collection's entries, a class instance, an empty pool on a required prop): drives the one-line-per-file degenerate-prop warning and is cleared per-prop by `applyPropPresets`. Used by `detectScalingProps` for auto-scaling detection. |
| PropCombination | `Record<string, unknown>`. Concrete prop key-value set for one render. |
| Stratified sampling | When cartesian product >64, select combos covering each value ≥1× while capping total. Seeded PRNG (42) fills remaining budget. `countCombinationSpace(schemas)` returns the raw cartesian size (display-capped at 1e9 by callers); `STRATIFIED_SAMPLE_WARNING(raw, sampled)` discloses the truncation. |
| MAX_DELTA_PAIRS | `128`. Cap on `generateDeltaPairs`' output. `countDeltaPairSpace(schemas)` returns the full pair count before the cap; `DELTA_PAIR_CAP_WARNING(measured, total)` discloses the truncation, on both the plain-combo and forced-matrix paths. |
| MATRIX_PAIRWISE_COVER_WARNING | `MATRIX_PAIRWISE_COVER_WARNING(covered, full)`. Emitted when a matrix's full cartesian cell count exceeds `MAX_MATRIX_CELLS` (256) and `generatePropMatrix` fell back to `pairwiseCover`: every value pair tested at least once, not every cell. |
| MATRIX_AUTO_ACTIVATED_NOTICE | `MATRIX_AUTO_ACTIVATED_NOTICE(cellCount)`. Printed to stdout (non-`--ci` only) before measurement starts when matrix mode auto-activated (`shouldAutoActivateMatrix`), naming the cell count and that `--no-matrix` disables it. Not shown for an explicit `--matrix`, since that was the user's own request. |
| MATRIX_BASELINE_WARNING | M54. Pushed to `Report.warnings` when a matrix run was given a baseline flag (`baselineWorkflowRequested`: `--save-baseline`, or `--check`/`--budget` without `--no-baseline`). The matrix path returns before `applyBaselineWorkflow`, so those flags do nothing; the warning names that and `--no-matrix` as the workaround. Fires for auto-activated and explicit `--matrix` alike, `--ci` included. |
| computeEffectiveSamples | `computeEffectiveSamples(comboCount, samples)` → `number`. Above 20 combos/cells, throttles the sample count to `max(3, min(samples, floor(200 / comboCount)))`; applies identically to the plain-combo and forced-`--matrix` paths. |
| ProjectModel | `{ memberRoot, workspaceRoot }` from `resolveProjectModel(dir)` (M68). `memberRoot`: nearest ancestor with a `package.json` (`findProjectRoot`, moved to `project-model.ts`, re-exported from `harness.ts`) — unchanged semantics: harness dir, Vite root, relative component key, baseline location. `workspaceRoot`: nearest ancestor at or above `memberRoot` that governs the install (`findWorkspaceRoot`): first hit of `pnpm-workspace.yaml`, a `package.json` `workspaces` field, or a lockfile (`WORKSPACE_LOCKFILES`) wins; the walk stops after a directory holding `.git`; no hit → `memberRoot`. Equal to `memberRoot` outside a workspace, the invariant every pre-M68 test encodes. |
| isPackageDeclared / isPackageAvailable | `isPackageDeclared(pkg, memberRoot, workspaceRoot?)` (M68): `pkg` named in either root's `dependencies`/`devDependencies`/`peerDependencies` (`declaredPackages`). `isPackageAvailable(pkg, memberRoot, workspaceRoot?)`: declared as above, or a `<level>/node_modules/<pkg>/package.json` probe (`workspaceLevels`, `memberRoot` up to `workspaceRoot`) — deliberately not `require.resolve`, which honours `NODE_PATH` and resolves symlinks past the level it names. Every M68 detector switched to one of these; only `detectReactCompiler` stays declaration-only, because the compiler rewrites measured code and a hoisted transitive copy is not a statement the project ships it. |
| findCompilerConfig | `findCompilerConfig(startDir, stopDir?)` (M69) → forward-slashed absolute path or `undefined`. Walks upward from `startDir`; the first `tsconfig.json`, then `jsconfig.json`, found at a level wins; the walk stops after `stopDir` (default: the filesystem root). Shared by `loadTsconfigAliases` (`src/harness.ts`, bounded by `findWorkspaceRoot`) and prop extraction's `createCompilerOptions` (`src/prop-gen.ts`), which previously disagreed about which config governed a workspace member. |
| detectPnP | `detectPnP(workspaceRoot)` → `boolean` (M72). True when `process.versions.pnp !== undefined`, or `.pnp.cjs`/`.pnp.loader.mjs` exists at `workspaceRoot`. `runPreflight` pushes a hard `"yarn-pnp"` hit unconditionally when true: a PnP install is a resolution-mechanism problem this harness cannot read, not a framework choice. |
| HarnessResult | `{ url, server: ViteDevServer, componentPath, harnessDir, cleanup, component: ComponentIdentity, nextJsShims?, wrapPath?, wrapRelative?, cssFiles?, reactCompiler? }`. Return value of `buildAndServe()`. |
| ComponentIdentity | `{ relative, name, isDefaultExport }`. The component the entry mounts, carried on `HarnessResult` so the React probe entry does not re-parse the generated entry. On the composed path, `name` is the composition root. |
| Control API | `window.__120fps`: `mount(props)`, `mountWrapperOnly()`, `unmount()`, `rerender(props)`, `getContainer()`, plus `viewport` when the provider wrapper exports one. Harness exposes these for CDP-driven measurement. |
| Provider wrapper | User-authored module default-exporting a `{ children }` component, rendered around the component under test so context-dependent components mount. Resolved from `--wrap <path>` or auto-detected as `120fps.setup.{tsx,jsx,ts,js}` at the project root; disabled with `--no-wrap`. Imported before the component so its top-level side effects (CSS import, `data-theme`) run first. |
| renderTree | Entry-template helper `(el) => root.render(wrap ? createElement(wrap, null, inStrict(el)) : inStrict(el))`. Single render site per entry; every mount/rerender/scale path routes through it, so a wrapper applies once even to an auto-scale fan-out. `renderTreeHelper(wrapRelative, strict?)` emits the StrictMode form only for the two measurement templates; the React probe entry keeps the plain one. |
| `__120fpsInStrict` | Entry-template helper wrapping the tree in `React.StrictMode` when the page URL carries `?strict=1`, and returning it untouched otherwise. Nests inside the provider wrapper, so the measured double-invoke cost is the component's rather than the providers'. Named to avoid the `__120fpsWrap` prefix, which an entry without a wrapper must never contain. |
| detectWrapper | `detectWrapper(projectRoot)` → `string \| undefined`. Probes `120fps.setup.tsx`, `.jsx`, `.ts`, `.js` in that order; first file hit wins. |
| WrapperReport | `{ path, autoDetected, overheadMs, domNodes, hasSetup? }` on `Report.wrapper`. `path` is projectRoot-relative posix. `attachWrapperReport()` sets it and appends warnings when `overheadMs >= 1` or `domNodes > 0`. |
| measureWrapperOverhead | `measureWrapperOverhead(page, cdp, samples)` → `{ overheadMs, domNodes }`. 2 discarded warmups, then per sample: GC → traced `mountWrapperOnly()` + double-rAF → untraced `unmount()`. `domNodes` is the wrapper-only node delta, clamped to ≥ 0. |
| applyWrapperViewport | `applyWrapperViewport(page)`. Reads `window.__120fps.viewport` in the browser and applies it via `page.setViewportSize` after the readiness gate, before throttle and warmup. Non-numeric or non-positive values are ignored. |
| Stylesheet injection | Global stylesheets emitted as side-effect imports at the top of the generated entry, ahead of the React, wrapper, and component imports, in priority order (M71, `discoverGlobalCss`): explicit `--css`, then the entry-import-graph layer (`findProjectEntry` + `entryStylesheetImports`, tsconfig-alias-resolved, preprocessor-gated), then the filename-candidate layer (`detectGlobalCss`), then a bounded `largestStylesheet` fallback that warns it guessed. First layer to yield at least one validated file wins; auto-detection can inject more than one file, in import order. Disabled with `--no-css`. Root-absolute specifier inside `projectRoot`, `/@fs/<abs>` outside it. `index.html` is never touched. |
| detectGlobalCss | `detectGlobalCss(projectRoot)` → `string \| undefined`. The filename-candidate layer of `discoverGlobalCss` (M71), unchanged meaning: probes `GLOBAL_CSS_CANDIDATES` (18 entries: the original 8 filenames plus `src/style.css` and every `.scss` variant) in order; first existing file wins; directories are skipped. Returns at most one file. |
| resolveCssFiles | `resolveCssFiles(options, projectRoot, warningsOut?)` → `{ files, autoDetected }` with absolute paths. `noCss` wins over explicit paths and skips their validation. Explicit paths resolve against `process.cwd()`, dedupe by resolved path keeping first position, and suppress detection; an empty explicit list falls through to detection. Missing → `Stylesheet not found: <path>`; non-file → `Stylesheet is not a file: <path>`. The optional `warningsOut` sink (M71) collects discovery warnings (a skipped preprocessor import, a fallback guess) without changing the return shape. |
| cssImportSpecifier | `cssImportSpecifier(cssFile, projectRoot)` → `string`. Posix specifier for the entry import: `/<relative>` when the file is inside `projectRoot`, `/@fs/<absolute>` otherwise (drive letter preserved, spaces kept). |
| CssReport | `{ files: string[], autoDetected: boolean }` on `Report.css`. `files` are projectRoot-relative posix paths in injection order. Absent when nothing was injected. Rendered by `formatTable` as a `Stylesheets:` header line and passed to `buildEnvFingerprint` as `css`. |
| detectTailwindVite | `detectTailwindVite(projectRoot)` → `boolean`. `isPackageAvailable("@tailwindcss/vite", projectRoot)` (M68): declared at either workspace level, or installed at any level between them. |
| loadTailwindVitePlugin | `loadTailwindVitePlugin(projectRoot)` → `Promise<unknown[]>`. Resolves and imports `@tailwindcss/vite` from the project's own `node_modules` via `createRequire(projectRoot + "/")` and calls its default export. Any failure writes one stderr warning and returns `[]`. Only called when injection is active. A project `postcss.config.*` still runs alongside it. |
| React Compiler transform | `@vitejs/plugin-react` added to the harness Vite config with `babel.plugins: [[<project-resolved babel-plugin-react-compiler>, {}]]`, so a project that ships compiled code is measured compiled. Added if and only if the transform is active, appended after M25's Tailwind plugin. `--react-compiler` forces it on, `--no-react-compiler` off, otherwise `detectReactCompiler` decides. |
| detectReactCompiler | `detectReactCompiler(projectRoot)` → `boolean`. `isPackageDeclared(REACT_COMPILER_PACKAGE, projectRoot)` (M68): declaration only, at `projectRoot` or its `workspaceRoot`, deliberately never an install probe — the compiler rewrites the code being measured, and a hoisted transitive copy is not a statement the project ships it. Missing, unparseable or non-object manifests, and non-object dependency sections, read as absent. `next.config.*` is never parsed. |
| resolveReactCompiler | `resolveReactCompiler(projectRoot)` → `{ pluginPath?, version? }`. Resolves `babel-plugin-react-compiler` through `createRequire(projectRoot + "/")` so the project's own copy is used. `version` comes from the first `package.json` above the resolved entry, and only when its `name` matches. Any resolution failure returns `{}`. |
| ReactCompilerState | `{ detected, active, version?, pluginPath?, warning? }` on `HarnessResult.reactCompiler`. Carries at most one warning, so the disabled note and the resolution note can never both reach a report. Forced on with nothing resolvable throws `babel-plugin-react-compiler not found in <projectRoot>` before the harness directory is created. |
| loadReactCompilerPlugin | `loadReactCompilerPlugin(pluginPath)` → `Promise<unknown[]>`. Dynamically imports `@vitejs/plugin-react` (a 120fps dependency) and calls it with the compiler path as a babel plugin. Dynamic so an uncompiled run never loads `@babel/core`. |
| reactCompilerRuntimeDeps | `reactCompilerRuntimeDeps(projectRoot)` → `string[]`. `["react/compiler-runtime"]` when the project resolves it, else `[]`. Added to `optimizeDeps.include` while the transform is active: compiled output imports that module, and leaving it undeclared makes Vite re-optimize and full-reload on the first page load. |
| ReactCompilerReport | `{ active, detected, version? }` on `Report.reactCompiler`. Present whenever the compiler was detected or ran. `formatTable` prints `React Compiler: active (v<version>)` only when `active`. |
| Settle gate | `settleStyles(page, harness)`. Armed by `needsStyleSettle` when stylesheets are injected or a provider wrapper is active. Awaits `document.fonts.ready` bounded by `FONT_SETTLE_TIMEOUT_MS` (5000), then forces one layout and waits two rAF ticks (10s starvation watchdog); returns whether fonts settled. Runs in all five browser sessions after `applyWrapperViewport` and before CPU throttling. A missing `document.fonts` skips straight through. A timeout is non-fatal: `analyze()` appends `FONT_SETTLE_WARNING` to `Report.warnings`. |
| Driven pacing | M35. Lifecycle measurement browsers launch with `MEASUREMENT_BROWSER_ARGS` (`--enable-begin-frame-control --run-all-compositor-stages-before-draw`) and a frame pump drives the compositor via `HeadlessExperimental.beginFrame`, so a double-rAF fence costs ~2ms instead of two 60Hz vsync ticks (~33ms). Frames still happen: driven, not scheduled. Explore and react-analysis sessions keep vsync pacing (their metrics depend on real frame scheduling); combos that animate are re-measured under vsync. `MountResult.pacing` / `RerenderResult.pacing` record which pacing produced each combo. |
| Frame pump | `createFramePump(holder, options?)` → `{ stop(), disabled }`. Sends `beginFrame` back-to-back, reading `holder.cdp` on every frame so it follows `refreshCdpSession`. Transient errors back off 5ms; 120 consecutive failures disable it (`FRAME_PUMP_WARNING`). Begin-frame support is probed once at session entry (`openMeasurementSession`); probe failure reopens a plain vsync browser for the whole pass. |
| rAF fence | `rafFence(page)`. The double-rAF settle fence used after every mount/unmount/rerender, with a 10s watchdog that converts frame starvation (a begin-frame browser whose pump died) into a failed run instead of an infinite hang. |
| HARNESS_NAV_WAIT | `"domcontentloaded"`. Navigation wait for every harness `page.goto`. Readiness is `window.__120fps`; the `load` event is unusable because a stylesheet whose webfont never answers keeps it pending. |
| enterHarness | `enterHarness(page, cdp, harness, errorCapture, { label, cpuThrottle?, search? })`. The session preamble: navigate to `harness.url + search` → `window.__120fps` readiness gate (30s, `enrichTimeoutError` with `label`) → `applyWrapperViewport` → `installMeasuredStateProbe` → `settleStyles` → `Emulation.setCPUThrottlingRate`. Re-runnable, so a pass that navigates mid-session repeats all of it. |
| Compare mode | M49. `--compare <gitref>` measures the working tree against a ref with samples **interleaved** per sample across both sides in one window, over the same pooled browser. Reference side via `git worktree add --detach`, preceded by a best-effort `pruneStaleWorktrees` (M70) clearing any registration a hard-killed prior run left dangling; every directory from the repo root down to the measured workspace member that has its own `node_modules` is linked in (junction on Windows; `nodeModulesLinkDirs` + `linkNodeModules`, M68), so a pnpm workspace member's own dependencies resolve on the reference side too, which the matching-lockfile guard is what makes sound. Mount, unmount and DOM count only; combos come from the working tree's schema. No verdict, no exit code. |
| distinguishable | M49. Compares sample **ranges**, not means: only non-overlapping spreads say the difference outlived the noise. Deliberately not a t-test. |
| formatMarkdown / formatJUnit | M50. Pure serializers over `Report` for `--report-md` and `--report-junit`. No measurement state, no filesystem, no network: 120fps emits what forges consume and never talks to a forge. Markdown keeps regression detail behind a `<details>` fold so a large sweep fits a comment; both files are written even when components failed. |
| Hints | M51. Ten finding classes map to an action plus a README anchor (`src/hints.ts`). `hintsForReport` derives the set from the report alone; every output mode prints them once per run via `appendHints`, and `Report.hints` carries ids rather than prose so wording changes without schema churn. |
| MEASUREMENT_BASIS_LINE | M51. One line in every report header: 4x CPU throttle, budgets calibrated for it, numbers comparative rather than production wall-clock. |
| Project transforms | M48. `SUPPORTED_TRANSFORM_PLUGINS` (SVGR, vanilla-extract) detected via `detectProjectTransforms` (`isPackageAvailable` at the member root and its `workspaceRoot`, M68), resolved from the project's own `node_modules`, appended to the harness Vite config with `configureServer`/`configurePreviewServer`/`handleHotUpdate`/`hotUpdate` stripped. Verified end to end by the M48 spike: hook-stripping is sufficient isolation for both. Load failure warns and continues; active transforms join the M39 fingerprint and `Report.projectTransforms`. `--no-transforms` opts out. |
| resolvePluginFactory | M48. `resolvePluginFactory(mod, exportName?)`. Three shapes seen in the wild: a real default export, a CJS package double-wrapped by interop (`mod.default.default`, e.g. `vite-plugin-svgr`), and a factory that is only a named export (`vanillaExtractPlugin`). `mod.default ?? mod` fails the latter two. |
| Observers | M52. `installObservers`/`beginObservedWindow`/`readObservedWindow` collect Event Timing, Long Animation Frame and layout-instability entries in-page, scoped to a window by start time rather than by clearing buffers. `EVENT_TIMING_THRESHOLD_MS` is 16 (the API's documented minimum); nothing below it is observable, and `observedInteractionMs` falls back to LoAF blocking time there. It reports the window's slowest interaction, never a total: Chromium emits one entry per dispatch target, so 11 clicks arrive as 62 entries. Opt-in via `ExploreOptions.observerTiming`; explore times through CDP traces by default. The switch-over was rejected rather than deferred, on two measurements: the A/B ratio is 0.93 against a ≤0.50 target (the trace lifecycle is 4% of explore's wall clock, the per-step settle 91%), and observers report 0.00ms/step for components the trace path measures at 0.5–1.0ms/step. |
| probeVolatileRegions | M47. `probeVolatileRegions(page, gapMs?)` → structural paths whose content moved between two idle samples `VOLATILITY_PROBE_GAP_MS` (250) apart. Runs once per combo before discovery and before the initial hash. A path present in only one sample is a structural difference and is never volatile. |
| Volatile-aware DOM hash | M47. `computeDomHash(page, volatilePaths)` walks the tree instead of reading innerHTML. Volatile subtrees drop text and attribute values but keep tags, element presence and attribute names: structural change through a volatile region still counts as state, content churn inside it does not. Region identity is `/TAG[index]` from `#root`, so a remount maps to the same regions. |
| VOLATILE_DOM_NOTICE | M47. Run-level notice naming the combo and how many regions changed without input. Volatility affects state attribution only: never discovery, cost measurement, or DOM counts. |
| NoiseReport | M46. `Report.noise = { level: "quiet" \| "noisy" \| "hostile", signals }`. Signals: `probeCv`/`probeMedianMs` (dispersion of a fixed busy loop, 7 samples, unthrottled, outside traced windows), `unstableFraction` (share of metrics the CV rule flagged), `contextRetries` (M30 reloads, counted before warning dedup). |
| classifyNoise | `noisy` at `probeCv > NOISE_CV_PERCENT` (15): the same bar `buildTimingWithCV` uses to distrust a metric: or `unstableFraction >= 0.25`, or any retry. `hostile` at twice the CV bar or `unstableFraction >= 0.5`. Thresholds are derived from the existing CV rule, not fitted to measured distributions. |
| probeMachineNoise | `probeMachineNoise(page, samples?)` → timings of a fixed arithmetic loop. Deliberately not calibration: that measures a DOM insert plus layout, feeds normalization, and swings 20–40% per sample (M39). |
| Noise consequences | `noisy` warns and stops baseline regressions from failing the run (budget verdicts are absolute and unaffected); `hostile` skips baseline comparison and sets `BaselineComparison.skippedNoisy`; `quiet` changes nothing. Mirrors M22's unstable-metric downgrade, run-scoped instead of metric-scoped. Never gates M39 reuse: a cached verdict measured nothing. |
| Baseline slots | M45. Baseline entries are keyed `<component>#<envKey>`: one slot per environment in one committed file. Composite keys, not nesting: the map stays `Record<string, BaselineEntry>`, sorted keys group by component, and branches touching different components merge textually. File version 2; version-1 files are rekeyed in memory on load, and entries with no `env` land in a `legacy` slot that is readable but never written. |
| computeEnvKey | `computeEnvKey(env)` → 8-hex digest of machine identity: metrics revision, CPU, cores, OS, Chromium **major** version, throttle, samples, mode, css, wrapper, reactCompiler. Excludes calibration (a single sample swings 20–40%, so it would fragment slots by thermal luck) and the Chromium patch version. `undefined` env → `LEGACY_ENV_KEY`. |
| selectBaselineEntry | `selectBaselineEntry(baseline, componentPath, envKey)` → `{ entry, crossEnvironment }`. Exact slot first; otherwise the component's freshest other slot with `crossEnvironment: true`. Such a comparison informs and never fails a run: except under `--baseline-env ignore`, which opts out of the fallback marking entirely. |
| Slot pruning | `BASELINE_SLOT_TTL_DAYS` (90). `saveBaseline` drops slots not updated within the window and returns their keys for `PRUNED_SLOTS_NOTICE`. Never prunes the slot it just wrote; keeps slots with no `savedAt`, which predate M45: absence is not age. |
| Prop presets | M44. `<stem>.props.tsx\|ts` next to the component, auto-detected like a fixture. Default export maps prop names to a value or array of values (a bare value is a one-element pool). Values **replace** the synthesized pool in `PropSchema.values`, so they reach combos, deltas, matrix cells and curve anchors through one seam. Never applies in fixture mode. |
| loadPropPresets | `loadPropPresets(presetPath, projectRoot)` → `PropPresets \| undefined`. Parses the module with the TS AST and never executes it. Literal expressions (string/number/boolean/null/undefined/negative, and arrays/objects of them) become real values; everything else becomes a `PresetRef`. Returns `undefined` for a missing file or a module with no object default export. |
| PresetRef | `{ __120fps_preset: propName, index }`. A value's position rather than the value: functions and JSX cannot cross the CDP boundary. `presetResolverBlock` substitutes the real value in the page at `mount`/`rerender`. |
| applyPropPresets | `applyPropPresets(schemas, presets)` → `{ schemas, applied, unknown }`. Replaces value pools for named props; an empty pool is ignored so a prop is never blanked out. `unknown` drives `UNKNOWN_PRESET_PROPS_WARNING`. |
| propPresets (report) | `Report.propPresets = { path, props }`. The preset module (projectRoot-relative posix) and the prop names it actually fed. The file also joins the M39 source fingerprint: nothing in the component graph imports it. |
| runPreflight | M42. `runPreflight({ projectRoot, entries, componentName? })` → `{ hard: PreflightHit[], soft: PreflightHit[] }`. BFS over runtime import edges from the measured file and the wrapper, before any harness exists. Parses with `ts.createSourceFile` and resolves with `ts.resolveModuleName` under `projectCompilerOptions`: no type checker. Stops at `node_modules` and `.d.ts`. |
| PreflightHit | `{ kind: "server-only" \| "use-server" \| "async-component" \| "node-builtin", chain: string[], specifier? }`. `chain` is projectRoot-relative posix, measured file first, reconstructed from the BFS parent map. |
| preflightFailureMessage | M42. Renders the first hard hit as `chain → specifier` with the cause, the fix ("extract the client part below that boundary"), and `--no-preflight`. First hit only: everything below it is unreachable until that edge moves. |
| NODE_BUILTIN_WARNING | M42. Soft signal for a Node builtin (`node:*` or a `module.builtinModules` name) in the graph. Not suppressible: Vite may externalize it, so it is a lead, not a verdict. |
| PREFLIGHT_BYPASSED_WARNING | M42. Emitted when `--no-preflight` downgrades hard findings, naming each bypassed chain. |
| projectCompilerOptions | `projectCompilerOptions(absolutePath)` → `ts.CompilerOptions`. The tsconfig-derived options prop extraction resolves under, exported so the M42 preflight walks the same graph with the same `paths`. |
| setupBlock | M41. `setupBlock(wrapRelative?)` → entry source. Emits a top-level `await` of the wrapper's `setup` export ahead of the `window.__120fps` assignment, raced against `WRAPPER_SETUP_TIMEOUT_MS` (15000). Empty without a wrapper, so a wrapper-less entry gains neither a top-level await nor a reference to `__120fpsWrapModule`. Used by the standard, composed and probe entries. |
| setupApiBlock | M41. `setupApiBlock(wrapRelative?)` → entry source appended after the control API assignment: `__120fps.hasSetup` (whether `setup` was callable) and `__120fps.teardown()` (invokes the wrapper's `teardown` export). Empty without a wrapper. |
| runWrapperTeardown | M41. `runWrapperTeardown(page)`. Calls `__120fps.teardown?.()` once from `MeasurementSession.close()`, before the page is disposed. Session-scoped, not per-unmount: `unmount()` runs once per sample inside the traced window. Swallows every error: a closed page or a throwing teardown must not fail a completed measurement. |
| MeasuredState | M40. `"settled" | "pending-network" | "late-mutation"` on `ComboReport.measuredState`, `MountResult.measuredState` and `BaselineEntry.measuredState`. What scene the numbers describe. `classifyMeasuredState({ pendingNetwork, mutated, hasAnimation })` decides: network wins when both fire; `mutated` is ignored when `hasAnimation` (animation mutates by design). |
| installMeasuredStateProbe | `installMeasuredStateProbe(page)`. Wraps the page's `fetch` and `XMLHttpRequest.prototype.send` behind a `window.__120fpsNet` guard (idempotent). Each request takes a monotonic id held in a pending set until its promise settles (`loadend` for XHR). Installed in `enterHarness` before anything mounts, so every sample runs under identical instrumentation. Deliberately not CDP's `Network` domain: its event traffic lands inside traced windows. |
| readNetworkProbe | `readNetworkProbe(page)` → `{ started, pending: number[] }`. Read before the mount and after the grace window; `pending.some(id => id > startedBefore)` is the `pending-network` signal, so a request left hanging by an earlier combo does not flag the next one. |
| probeLateMutation | `probeLateMutation(page, holdMs, observe)` → `boolean`. Holds `holdMs` of real time and reports whether the component DOM moved. Observes `#root` subtree, body portal children, and `document.body` at `childList` (late portals). `observe: false` still holds: the network signal reads after the same window either way, and animated combos take that path. |
| MEASURED_STATE_HOLD_MS | `120`. The grace window after the mount fence, in real time. Long enough for a promise-resolution or short-timer re-render to land, short enough that every combo pays it once. Timers run on wall clock under the frame pump, which keeps driving frames throughout. |
| MEASURED_STATE_WARNING | `MEASURED_STATE_WARNING(state, combo?)`. Run-level disclosure for a non-settled combo, naming the combo and the signal. Omitting `combo` produces the reused-baseline wording for an M39 cached verdict. Warns, never fails. |
| measuredStateMismatch | `BaselineComparison.measuredStateMismatch: { baseline, current }`. Set when the entry and the current run recorded different `measuredState` values; regression analysis is skipped and `analyze` warns. Only observable when both sides recorded a state: a pre-M40 entry compares normally. |
| runHarnessSession | `runHarnessSession(harness, options, body)`. Opens a measurement session (driven pacing unless `options.pacing` is `"vsync"`), runs `enterHarness`, then calls `body(page, cdp, enter)` and closes the session in `finally`. `enter(search?)` re-navigates within the same page. |

|---|---|
| Renderer | `"react" \| "vue"`, chosen by `rendererFor(filePath)` from the measured file's extension. Decides the entry template, its filename (`entry.tsx` vs `entry.ts`), `optimizeDeps.include` and `resolve.dedupe`. The file's own type is stronger evidence than package.json or `--framework`. |
