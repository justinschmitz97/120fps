## Goal

A developer points `120fps` at a component in a typical frontend — Vite React or Vue, Next.js app and
pages, RR7/Remix, Nuxt, T3, shadcn, Tailwind, a monorepo app — and the run is fast, quiet and true.
A failure before readiness ends within seconds of the throw, with the bound it advertised. An unbuilt
workspace sibling is walked, typed and aliased as its own package. The stylesheet the app loads is
found where the app loads it. Every warning on a passing run is true, printed once, and names what to
do. A render failure names its provider and its bad value and nothing that never rendered. A passing
run pays for each distinct prop set once and labels its phases truthfully. The dry run resolves each
module and reads each tsconfig once. A Vue app's generated auto-import maps resolve its components.

## Rules for every worker

- **Spec before code.** The lane's spec (`specs/milestones/m1NN-<slug>.md`, `status: draft`) is
  approved by the coordinator before the first test is written. If implementation contradicts the
  spec, stop and amend the spec first; never silently change either.
- **Failing test first.** Each MUST maps to at least one test that fails for the right reason before
  any source line changes; each MUST NOT maps to at least one negative test.
- **Behaviour-named tests.** `test/unit/<what-the-system-does>.test.ts`. No `mNNN` token in a file
  name, a `describe` title or an `it` title. A lane may extend an existing test file that exercises
  its own files (listed above); it never edits another lane's test file.
- **Fixtures are add-only.** New directories under `fixtures/`; never edit an existing fixture.
- **LF line endings.** `git ls-files --eol` reports every `src/` and `test/` file as `i/lf w/lf` at
  `f54be55` (525 files, `.gitattributes` pins `src/**` and `test/**`). Keep it so; after any scripted
  edit, `git diff --numstat` must show only the lines you meant to change.
- **Edit, never `Write`, an existing source file.** Re-read the region (`grep -n`, then a bounded
  `sed -n`) immediately before each edit. New files may be written whole.
- **One vitest process per lane**: `npx vitest run <files> --maxWorkers=2`. Never the e2e suite unless
  the spec names the file. `dist/` must be built before the unit suite
  (`node node_modules/typescript/bin/tsc -p tsconfig.json`).
- **Full unit suite once before the lane's final commit**: `npx vitest run test/unit --maxWorkers=2`,
  compared against the baseline totals recorded below. A new failure blocks the commit.
- **Commit per milestone** on the lane branch, message `M1NN: <title>`, carrying the spec, the tests
  and the code. No `git stash`, no `git checkout --` on a file you did not change, no rebase.
- **Never edit a target repository.** Corpus repos under `E:/repositories*` are read-only inputs. A
  run that leaves a file behind (`120fps-baseline.json`, `120fps-report*.json`, `.120fps-harness-*`)
  is a defect to report, not to clean up by hand.
- **Corpus repros only through the fieldtest runner**, against a `dist` built in the lane's own
  worktree (`node node_modules/typescript/bin/tsc -p tsconfig.json`):

  ```
  node C:/Projekte/120fps-fieldtest/tools/run120.mjs \
    --cwd <appDir> \
    --out C:/Projekte/120fps-fieldtest/logs/run7-lane-<x>/<repo> \
    --label <label> \
    --cli C:/Projekte/120fps-run7-lane-<x>/dist/cli/main.js \
    -- <args>
  ```

  `<appDir>` is `root` joined with `appDir` from `corpus/CORPUS-run7.tsv`; the default profile is
  `--samples 3 --max-combos 2 --explore-budget 30 --no-deltas`. One corpus run at a time per lane.
- **Node is not on the Bash PATH**: `export PATH=/c/Users/justi/AppData/Local/nvm/v22.22.2:$PATH`.
- **Report format**: `## changed` (path, one line each), `## verified` (commands and verbatim
  results), `## facts` (anything the findings claimed that live code contradicts, with `file:line`),
  `## open` (decisions only the coordinator can make).

Rule notes this run's reviews kept re-deriving, worth carrying into the next one:

- **Withholding a verdict on machine noise was evaluated and removed (M137 C4-C5).** The candidate
  gate would have swallowed the per-step interaction FAIL almost entirely (217 of 278 recorded runs
  classified `hostile`); its signal was circular (`classifyNoise` reaches `hostile` through
  `unstableFraction`, which counts the component's own metrics, so a jittery component would excuse
  its own machine); its reconstruction picked the wrong budget shape in the applied direction; and it
  contradicted the standing, already-approved contract that budget verdicts are absolute
  (`specs/overview/00-tdd.md:839`, `01-glossary.md:71`). Removed rather than shipped; a future gate
  that wants this must read the probe signal alone, carry a magnitude ceiling, and amend that
  contract first.
- **A synthetic curve's scale probes carry the first combo's real props (M134 C7).** They used to
  mount `{ __120fps_scaleN: n }` alone, so a component with a required prop rendered nothing on every
  scale row and threw `Element type is invalid ... got: undefined` (dub's `icon`, under M133's own
  synthesis). Spreading the first measured combo's props into each scale copy fixed it with no
  harness-entry change, because both mount templates already spread the rest of the object.
- **A measurement is only trusted when the thing it describes actually happened.** The same shape
  recurred three times this run: a growth hint must never be fitted over a combo whose `renderHealth`
  is `error`, in combo mode and curve mode alike (M133 C4); explore must not measure the browser's own
  attempt to leave the page rather than the component (M137); and a Vue component registered from a
  dependency's auto-import map must resolve inside real, executable source rather than being
  synthesized into a Nuxt context the harness does not have — M136's own C12 stop condition fired
  exactly here, when `@nuxt/ui`'s `<UCarousel>` resolved, then failed to load, and `defineAsyncComponent`
  turned that failure into a silent, empty-tree **pass**. The shared lesson: disclose what cannot be
  measured; never let an absence render as a pass.
