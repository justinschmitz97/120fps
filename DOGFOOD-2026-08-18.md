# Dogfood Report — Six React Projects (2026-08-18)

Six agents ran 120fps v0.3.0 (dist build from `main` @ `9dd2f80`) against every React-based project in `C:\Projekte`: **color-generator**, **constructia**, **focusrings**, **trnscrpt**, **kaninchen** (Next.js 16), **justinschmitz.de** (Next.js 16). ~24 CLI runs across ~30 real components, plus `--isolate memory`, `--curve`, `--matrix`, multi-component sweeps, `--no-shims`, and server-component preflight probes.

**Measurement caveat:** up to 3 runs shared the machine concurrently, so the noise sentinel classified nearly every run hostile. Timing magnitudes below are provisional; bug reproductions, root causes, and output/UX observations are not noise-sensitive.

**Verdict in one paragraph:** the measurement machinery held up — harness build, CDP timing, memory isolation, preflight, and exit codes were consistent everywhere. But prop extraction and error visibility have trust-destroying bugs: in 4 of 6 projects the tool confidently reported PASS/FAIL verdicts for runs that never exercised the real component, and components that crash on mount report PASS. Most findings below are root-caused to file:line; hypotheses are labeled.

## P0 — silent wrong data

### 1. Prop extraction binds to the wrong component (4 projects, 6 components)

`findComponentPropsType` (`src/prop-gen.ts:371-423`) walks top-level declarations via `ts.forEachChild` in file order and takes the **first** props-shaped match (`if (propsType) return` short-circuit). The variable-statement branch (`:407-419`) lacks even the PascalCase check the function-declaration branch has, and the result is never cross-checked against the component name `detectComponentName()` (analyze.ts) independently — and correctly — resolves. Any internal helper declared earlier in the file hijacks the schema.

Reproductions:

| Project | File | Measured props belong to |
|---|---|---|
| color-generator | `colorpicker.tsx` (target `ColorPicker`) | internal `CanvasArea` (`{hue,saturation,lightness,dispatch}`) |
| focusrings | `switch.tsx` (target `Switch`) | internal `ThumbIcons` (`{isOn,iconOn,iconOff}`) |
| focusrings | `slider.tsx` (target `Slider`) | internal `SparkParticle` (`{spark,color}`) |
| focusrings | `colorpicker.tsx` (target `ColorPicker`) | internal `CanvasArea` |
| kaninchen | `hotspot-image.tsx` (target `HotspotImage`) | internal `Marker` (`{spot,isActive,isVisited}`) |
| justinschmitz.de | `Playground.tsx` (target `Playground`) | internal `FileTypeIcon` (`{filename}`) |

Consequences observed: entire multi-minute runs (12 combos, matrix cells, delta pairs, hints) measure the same default render repeatedly while reporting fabricated prop deltas (e.g. `isOn: false → true  mount -2.44ms` for a prop `Switch` does not accept); `--curve` silently no-ops because the real array prop (`presets`, `hotspots`) is masked (see P1 §7); required props of the real component (`files: SandpackFiles`) go unpopulated, crashing the mount — which is then masked by P0 §2. No warning is emitted in any case.

### 2. Components that crash on mount report PASS (4 projects, ~8 components)

Page errors are captured for the whole session (`src/page-errors.ts`, `attachPageErrorCapture` buffers `pageerror` + `console.error`) but the buffer is consumed **only** inside `enrichTimeoutError`, called from `src/analyze.ts:1881,1896`, `src/measure.ts:594,620`, `src/react-profiler.ts:546`, `src/explorer.ts:455`. A render that throws without causing a Playwright timeout is captured, then discarded.

Observed signature: `domNodeCount: 0` on every combo, zero interactions, zero cost-attribution entries, verdict **PASS**, exit 0, no error field anywhere in terminal or JSON — with plausible-looking mount times (the tool timed React mounting and unmounting a broken tree).

Reproductions:

- color-generator `ConfigRail.tsx` — `useWorkbench()` throws (`store.tsx:137-140`, missing `WorkbenchProvider`) on every mount → PASS/WARN(T1), 0 DOM nodes ×5 combos.
- constructia `Node.tsx`, `Graph.tsx` — object props degenerate to `{}` (P0 §3) → render crashes → PASS, 0 DOM nodes, despite an unconditional `<button onClick>` in Node's source.
- kaninchen `forecast-table.tsx`, `rabbit-form.tsx`, `health-check.tsx` (`--no-preflight`) — hypothesis (medium confidence): `useTranslations` throws without `NextIntlClientProvider` → PASS with 0 DOM nodes at every curve point, plus a spurious "exponential" growth hint over the empty renders.
- justinschmitz.de `comparison-slider.tsx` scale combos — `images` undefined → `images.length` throws → combos 4-7 PASS with 0 DOM nodes; `Playground.tsx` — `SandpackProvider` receives `files: undefined` (via P0 §1) → all 5 combos PASS, 0 DOM nodes.

Related gap, same mechanism: the initial `page.goto` calls are not wrapped by the enrichment at all (worker-traced in `dist/analyze.js:1423`, `dist/react-profiler.js:445`; only the subsequent `waitForFunction` is wrapped) — so some failures surface as a bare `page.goto: Timeout 30000ms exceeded` with zero diagnostics (justinschmitz.de `--no-shims` run; kaninchen `rabbit-form.tsx` first run). When the *waitForFunction* times out instead, enrichment works and prints useful page errors (`Module "node:path" has been externalized`, `process is not defined`) — the machinery exists, call-site coverage is incomplete.

### 3. Non-primitive prop types silently degenerate (4 projects)

- **Object domain types → `{}`**: constructia `node: Node`, `board: Board`; trnscrpt `options: MinimizeOptions` (10 boolean fields, none ever varied); kaninchen `spot` (via hijacked schema). Renders crash or measure empty trees.
- **Tuples → `{}`**: justinschmitz.de `images: [string, string]` — no tuple/arity handling in prop-gen; component measured against `<img src={undefined}>`.
- **cva `VariantProps<typeof x>` → `kind:"unknown"`, values `[]`**: trnscrpt Button/Badge/Alert. The standard shadcn/ui pattern is invisible — Alert's *only* prop is `variant`, so its whole run measures one combo forever and the `destructive` variant is never exercised.
- **Follow-on combo doubling**: `resolveValues` (worker-traced in `dist/prop-gen-values.js:139-145`) returns `[undefined]` for `kind:"unknown"`, then appends another `undefined` because the prop is optional → `[undefined, undefined]` cartesian-doubles every combo. Confirmed: trnscrpt button.json/badge.json contain byte-identical prop objects at combo indices 0/3, 1/4, 2/5 — half the combo budget spent on duplicates, presented as distinct rows.
- **`React.ComponentProps<typeof RadixPrimitive>` → no props**: color-generator `switch.tsx`, focusrings `tabs.tsx` (hypothesis on exact cause: computed/mapped type not resolved by `looksLikePropsType`). "No props extracted" warning is honest, but no resolution is attempted and nothing suggests the `<stem>.props.tsx` preset escape hatch.
- **`Map`/`ReadonlyMap` → `{}` in JSON `props`** — indistinguishable from a genuinely empty object.

No warning is emitted for any of these degradations.

## P1 — broken features and crashes

### 4. Next.js shim-usage reporting is a dead feature (100% reproducible, traced end-to-end)

`activeShims`/`report.nextJsShims` is always `undefined`, for every project, unconditionally. Root cause (worker-traced in `dist/harness.js:938`, i.e. `scanExternalDeps` in `src/harness.ts`): the shim-redirect alias (`^next/image$` → `shims/next-image.js`) is registered **before** the external-dep scan, so `resolveLocalImport(file, "next/image", ...)` matches the alias, returns the shim file's real path, and the specifier is treated as a **local** import — it never reaches the branch that records it in `specifiersOut`. `SHIM_MODULES.filter(s => importedSpecifiers.has(s.module))` is therefore always empty. The shims themselves work (next/image rendered fine in multiple runs); only the reporting never fires.

### 5. `Tracing.tracingComplete timed out` crash with zero diagnostics (2 projects, 2× each)

- trnscrpt `App.tsx` (Worker-backed `useExactTokens` hook, window-level drag/paste listeners) — exit 2, two-line error, no stack, no phase/combo context, no JSON; reproduced with `--samples 5 --max-combos 4`.
- kaninchen `multiselect.tsx` — identical signature, twice.
- Related: constructia `GameCreate.tsx` (wasm import) hung past the 600s Bash timeout twice with **zero output** — possibly the same class, unconfirmed.

Hypothesis (medium confidence): something keeps the page non-idle so CDP tracing never completes. There is no diagnostic surface to confirm from the outside.

### 6. Curve growth classification is unstable and self-contradictory

`computeScalingCurve` (worker-traced in `dist/metrics.js:408-419`) fits linear/quadratic/exponential and picks the highest raw R² with no margin or significance test. Observed:

- trnscrpt `DiffView`: default run → `linear`, PASS; identical component, explicit `--curve lines:array --samples 5` immediately after → `quadratic`, FAIL.
- Same screen contradiction: Growth column prints `linear` (mount) while the hint block warns "superlinear-growth" off a rerender curve classified `exponential` for medians growing 3.7× over a 50× N increase.
- kaninchen/constructia: "exponential" hints over degenerate 0-DOM renders (P0 §2).

### 7. `--curve` silently no-ops with no diagnostic (2 projects)

When the extracted schema has no array prop — including when P0 §1 masked a real one — `--curve` falls back to plain prop-combo mode and prints `Mode: prop combos`, indistinguishable from success. The user explicitly asked "does it scale with its data?" (the CLI's own help framing) and gets an answer to a different question. Expected: "no array/list prop found, --curve not activated."

### 8. `--max-combos` is ignored once matrix mode auto-activates

focusrings `badge.tsx` with `--max-combos 4` still ran the full 64-cell matrix (and the default cap of 8 was likewise ignored on the plain run). `--help` documents `--max-combos` as "Prop combos to measure" with no matrix carve-out.

### 9. Combo-count headers are internally contradictory (3 projects)

The 4 synthetic auto-scale combos are appended to every non-matrix run but counted inconsistently: focusrings `switch.tsx` printed `Mode: prop combos (12 measured of 8 generated)` (12 > 8); color-generator `colorpicker.tsx` header said "12 measured of 27" while the footer warning said "measured 8 of 27; 19 dropped."

### 10. `hasAnimation` false-positives on static CSS and force-sets T3

`detectAnimations` (`src/measure.ts:13-41`) flags any element whose *declared* `transition-property/duration` covers transform/opacity/width/height/all — not an actually-running animation. Tailwind's `transition-all` (shadcn `button.tsx`) trips it on idle, static toolbars. `classifyTier` (`src/report.ts:52`) then forces T3 unconditionally: constructia `GameControls` combo with 6 DOM nodes (documented T1 per the ≤10 rule) reported T3. Corroborated by `[anim]` WARN tags on static buttons in trnscrpt and color-generator. Compounds the known "portal/anim is an override, not a floor" backlog item.

### 11. Render attribution prints "Anonymous" for `memo(arrowFn)` exports

`src/react-profiler.ts:187` reads `fiber.type.displayName || fiber.type.name || "Anonymous"` without unwrapping — for `React.memo` the fiber type is the `{$$typeof, type: InnerFn}` wrapper (and `forwardRef` needs `.render.name`). kaninchen `Kbd` (`export const Kbd = memo(({...}) => ...)`) attributes every render to "Anonymous"; the pattern covers a large share of that codebase's components.

### 12. Compound-effect sign/word mismatch

`report.ts` (worker-traced at `dist/report.js:673`) prints the delta unconditionally as "above additive expectation": trnscrpt settings-dialog shows `open=true + selectedModel=X: -55.4ms above additive expectation (low)`. Negative deltas should read "below"/"cheaper than expected."

### 13. Cost-attribution totals don't reconcile with the Mount column

kaninchen `Kbd`: combo0 Mount median 5.08ms vs attribution total 26.85ms (5.3×); combo3 4.6×; combo5 2.9×. The ratio shrinks as N grows — the attribution trace window apparently covers more than the measured mount phase; nothing in the output explains the discrepancy.

### 14. `useReducer` `dispatch` flagged as unstable callback identity (hypothesis, 2 projects)

color-generator and focusrings ColorPicker runs both flagged `Callback identity: dispatch +6.6ms/+27.6ms`. React guarantees `dispatch` referential stability, so this reads as a false positive in the callback-identity delta measurement. Not root-caused.

## P2 — DX and output issues (each seen in 3+ projects unless noted)

- **WARN rows directly under "Result: PASS"** with no stated rollup rule (only `verdict === "fail"` affects `pass`, per `report.ts`; confirmed by a worker at dist `report.js:590`). Every worker independently flagged this as reading self-contradictory.
- **Synthetic N-copies scale combos are unlabeled**: `__120fps_scaleN` rows (N=1/5/20/50 sibling copies) interleave into the numbered combo table indistinguishable from real prop variations; "Scaling: linear" columns appear for components with no list props (constructia `GameControls` — two function props — got a full scalingCurve attached to *every* combo including non-scale ones, r²=0.9999); `__120fps_scaleN` leaks verbatim into JSON `combos[].props`; a "Dashboard at N=50: 3128ms mount, 11251 DOM nodes" row gives no clue it means "50 Dashboards side by side."
- **No cost cap or label on the scale probe**: focusrings colorpicker's single N=50 combo cost **46.9s**, slider's 11.8s — in default, non-`--curve` runs.
- **No progress output whatsoever**: 6m02s silent wall time on color-generator ColorPicker; silence is indistinguishable from the hangs in P1 §5. No total wall-clock printed either.
- **`HOSTILE_RUN_WARNING` wording** (`src/noise.ts:98-104`): fixed string always says "Baseline comparison was skipped" even when no `--check`/`--budget`/baseline was requested; the JSON's `noise.level`/`probeCv`/`unstableFraction` never appear in the terminal, which uses a different vocabulary ("too busy"); confident PASS/T1-T4 verdicts print right next to "treat every number as provisional" with no per-section trust guidance.
- **`--json` on multi-component runs silently becomes a per-component template** (`sweep.json` → `sweep.badge.json` etc.; the named file is never created, no message). A CI step reading `--json out.json` gets a missing file at exit 0. Also: sweep output order didn't match input argument order (badge, switch, kbd → badge, kbd, switch), no stated ordering rule.
- **"0 interactions found. Consider creating a fixture"** fires when the real cause is a crashed render (P0 §2 cases — a fixture wouldn't help) and for inherently non-interactive components (`Kbd`, a bare `<kbd>` tag).
- **Unrepresentative default combos**: `Kbd` measured 2 of 7 combos with `children` absent — the component early-returns `null`, so those rows contribute fake-fast numbers; `asChild: true` combos (Slot pattern) render nothing because no children are synthesized — half of Button/Badge's prop space measures an empty tree.
- **`componentName` from filename**: `health-check.tsx` reports `"Health-check"` instead of the exported `FoodHealthCheck`.
- **Curve-mode FAIL states no reason**: trnscrpt/constructia curve FAILs never name the violated threshold or the crossing point (user must manually diff rows against the 50ms budget to find it lands between n=5 and n=10).
- **Empty "React Optimizations" sections** print a header + blank `Combo #N:` line per combo when nothing was detected (constructia Node: 6 content-free lines).
- **JSON size**: badge.tsx's 64-cell matrix report is ~9,000 lines / 222KB for a 4-prop presentational leaf.
- **Curve-mode JSON has no top-level `mode` field** — consumers infer mode from the presence of `scalingCurveReport` vs `combos` (matches the known `report.mode` backlog item).
- **Stress-pattern semantics**: `rapid-toggle-11` (11 rapid clicks) applied to buttons labeled DELETE/LOAD; interaction rows print the descriptor type (`(focus)`) next to an unrelated executed pattern (`pointer-drag`, 60 steps) with an empty element label.
- **Callback synthesis undisclosed**: kaninchen RabbitForm's `onSubmit` absent from the JSON `props` dump on every combo, yet the optimization section reports `Callback identity: onSubmit +1.7ms` — a callback was synthesized and passed, just never shown.
- **Navigation timeout not adaptive**: hard-coded 30s `page.goto` timeout failed on first run (cold Vite pre-bundle of a heavy import graph), succeeded on retry — while the tool itself was reporting the machine hostile.

## Missing features (independently requested by 3+ workers)

1. **`--explain-props` / dry-run**: print resolved component name + extracted prop schema (+ file/line of the binding) without measuring. Would have exposed P0 §1 in seconds; four workers wanted it.
2. **Render-health gate**: `domNodeCount === 0` (or all combos far below expectation) + non-empty captured page errors → fail fast with the errors, never a verdict.
3. **Provider-dependency detection**: context/zustand/next-intl hooks in the import graph → specific "needs `--wrap`" message (mirroring the existing Next-shim/globals.css auto-detection UX). Currently these throw silently (P0 §2).
4. **Named-export targeting**: no way to measure `KbdCombo` over the default `Kbd` when auto-composition fails.
5. **Schema self-consistency check**: verify extracted prop keys against the destructured parameter names of the *target* declaration (cheap AST check; catches P0 §1 and §3 classes).
6. **Docs**: exit codes (0/1/2 — consistent everywhere but undocumented), `--json` multi-arg template behavior, `--max-combos` matrix carve-out, `--no-auto-scale` output shape.

## Improvement ideas (workers' proposals, deduplicated)

- Bind `findComponentPropsType` to the exported/target symbol: resolve exports first, then that identifier's props type; fall back with an explicit warning.
- Read `errorCapture.errors` unconditionally after every combo mount; attach to `combo.pageErrors` + a `[render error]` terminal marker. Wrap the initial `page.goto` call sites in the existing `enrichTimeoutError` pattern.
- Fix `scanExternalDeps` ordering: check `SHIM_MODULES` membership before/independently of alias resolution so shimmed specifiers are recorded (un-deadens §4).
- Extract cva variant keys as literal unions through `VariantProps<typeof x>`; handle tuples distinctly from open arrays/objects; serialize Map/Set as entry arrays; de-dup generated combos by stable-stringify before measuring (catches §3's doubling regardless of root cause).
- Require a margin (or AIC/BIC) over the linear fit before promoting to quadratic/exponential; state the violated threshold + crossing point on curve FAIL.
- Label scale-probe rows distinctly (`[×50 copies]`), never attach one combo's scalingCurve to others, and gate probe N by a cost estimate (skip/cap when the N=1 mount is already expensive).
- Gate `hasAnimation` on observed animation (`getAnimations()`, transition events), plus tier floor instead of override.
- Unwrap `memo`/`forwardRef` before reading `displayName`/`name` in render attribution.
- Progress heartbeat (`measuring combo N/M`), total wall-clock line, and phase/combo context on any crash (tracingComplete, goto timeout) with a hint ("check for Workers/long-lived timers — try `--explore-budget 0`").
- Make the hostile/noisy warning conditional on whether a baseline was actually requested; print `noise.level` + signals in the terminal text.
- Announce the per-component `--json` filename split; keep input order in sweep output.
- `--json-compact` (omit raw per-sample arrays) for small components.

## What held up

- **Exit-code semantics** (0 pass / 1 verdict fail / 2 setup-or-harness error) were consistent across all ~24 runs.
- **`--isolate memory`** was clean, fast, and correct in all 5 projects that ran it (+0.9 to +6.1KB/cycle, no false leaks, concise output).
- **Server-component preflight** rejected an RSC page cleanly with an actionable message; `--no-preflight` then produced a well-enriched module error.
- **Next.js shims functionally work** (next/image rendered and measured through them), the multi-component sweep path works with auto-named per-component JSONs, and auto-curve activation over a genuine array prop (`saves`, `lines`, `rows`, `images`) triggered correctly whenever the schema wasn't hijacked.
- The `--max-combos` drop warning ("measured 8 of 12... Raise it with --max-combos <n>") is the model of actionable wording the silent failures above should follow.

## Real component findings (side product, magnitudes provisional)

- **constructia `SavesList`**: mount scales linearly with `saves.length` (~4.75ms/item, r²=0.996), crosses the 50ms budget between 5 and 10 items, 244ms at 50 — no virtualization.
- **trnscrpt `SettingsDialog`**: `open=true` mounts at 150-190ms with 115 DOM nodes (T3/T4 FAIL) — dialog-open cost dominates.
- **justinschmitz.de `PortfolioSlider`**: linear mount growth with `images` (9→95ms, N=1→50); the component doubles the array internally for the marquee loop, so real cost is 2× the passed list length.
- **justinschmitz.de `Image`**: `priority: true` costs +9.5ms rerender vs `false` — surprisingly large for a boolean flip; worth a real profile.
- **kaninchen `RabbitForm`**: inline `onSubmit` changes identity every render, defeating downstream memoization (finding valid even though the run's render health is unverified per P0 §2).
- **color-generator `ColorPicker`**: canvas-area drag costs 0.9-2.1s under 4× throttle (real DOM-discovered interaction, unaffected by the prop hijack) — likely genuinely expensive (canvas repaint + worker + reducer chain).
- **color-generator `Dashboard`**: "Export" click interaction ~110ms (rapid-toggle-11) drives a T3 FAIL at realistic scale.
- Memory: no leaks anywhere.

## Open questions

- P1 §5 crashes (tracingComplete ×2 projects, wasm hang) are undiagnosed — the missing-diagnostics finding blocks external root-causing.
- Curve mode was never validated on a component that was simultaneously hijack-free *and* array-typed in the failing projects; DiffView/PortfolioSlider/SavesList suggest the mechanism itself works.
- `dispatch` callback-identity false positive (P1 §14) and the attribution/Mount window mismatch (P1 §13) are not root-caused.
- Whether a hand-written `<stem>.props.tsx` preset can work around the cva `kind:"unknown"` gap is untested.
- next-intl provider-throw hypothesis for kaninchen's 0-DOM runs is unconfirmed (would need the P0 §2 fix to see the actual error).

## Suggested fix order
